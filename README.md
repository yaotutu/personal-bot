# Pi Muse

> 开源的个人 Agent，以独立客户端体验为先。

喜欢 Muse 的界面与交互，于是我们基于 [pi](https://github.com/earendil-works/pi) 重新开发了一套个人 Agent：服务端与手机客户端源码开放，服务由你部署，日常在独立 App 中使用。

不只是把 Agent 接进一个聊天窗口，而是给它一个适合处理事情的界面：看进展、管任务、确认改动，再回到对话继续交流。

## 为什么做 Pi Muse

对我们来说，把 Agent 接进飞书、QQ 或微信，只解决了“在哪里发消息”，还没有解决“怎样用起来才顺手”。当它开始执行任务、等待审批、安排提醒、展示不同类型的内容时，把这些交互都压进消息气泡，很容易让使用体验受限。

**Pi Muse 的选择是：客户端优先，而不是先做一个聊天机器人，再给它补一个界面。** 聊天只是入口，运行状态、审批、任务和目标也应该有各自合适的位置。

我们也希望这个产品是开源的：不只让你下载一个 App，而是把服务端、客户端和接入接口都放在你看得见的地方。你可以自行部署，审阅它如何工作，并参与它接下来的演进。

## UI 与交互

**我们很喜欢 Muse 的 UI，这也是 Pi Muse 的起点之一。** 界面与交互设计借鉴 Muse，并参考了 [OpenMuse](https://github.com/CopilotKit/openmuse) 的移动端界面；Agent 执行则以 pi 为底座，重新开发服务端和独立移动客户端。Pi Muse 是独立项目，并非 Muse 或 OpenMuse 的官方版本。

我们借鉴的不只是配色和圆角，更是让个人 Agent 有一个完整使用界面的思路，并根据自己的能力重新组织交互：

| 不只是聊天里的文字 | 在客户端中怎样使用 |
| --- | --- |
| “正在处理” | 查看运行状态、工具调用与已登记工作的进展，需要时停止运行 |
| “是否同意修改” | 阅读完整修改预览，明确批准或拒绝，再查看执行回执 |
| “记得做这件事” | 在任务、目标与里程碑页面中查看和管理，而不是翻找聊天记录 |
| “换个事情聊” | 通过空间侧栏切换事务，保留各自的规则、对话上下文和工作区 |

胶囊输入区、揭示式空间侧栏、全屏会话面板，以及经典蓝白、晨光白、深夜黑三套主题，都围绕日常在手机上使用来设计。保留喜欢的视觉语言，同时围绕自己的能力和使用方式调整导航与交互。

## 开源与自部署

**开源不是附带选项，而是 Pi Muse 的重要前提。** 服务端和手机客户端的源码都公开，不只开放一个需要依赖封闭后端的前端界面。

- **源码可审阅**：了解 Agent 如何执行、数据如何保存、文件修改如何经过人工确认。
- **服务可自行部署**：运行在自己的电脑或服务器上，使用自己配置的模型服务，管理自己的会话、记忆与工作区数据。
- **客户端与接入接口都开放**：普通用户可以直接下载 App；开发者可以基于公开接口开发自己的客户端与接入方式，不必局限于官方 App。

查看源码：[服务端与项目主仓库](https://github.com/yaotutu/pi-muse) · [官方移动客户端](https://github.com/yaotutu/pi-muse-mobile)。自部署不等于所有推理都在本机完成，外部模型的数据边界见 [安全与隐私](#安全与隐私)。

## 核心体验

目前面向个人单用户使用，手机客户端以 Android 为主，iOS 仍在规划中。以下为当前源码中的能力，安装包的具体支持范围以对应版本发布说明为准：

- **偏好记忆与后台整理**：保存你的偏好与重要信息，需要时检索相关事实；还可按设置在后台整理长期记忆，减少反复交代背景。
- **目标与里程碑**：制定目标、管理里程碑，在手机上查看和跟进进度。
- **定时任务与网页监控**：通过对话创建一次性或每日任务，监测网页变化或关键词；在手机任务页查看和管理。
- **网络信息检索**：内置公开网页搜索、实时天气查询与指定网页内容抓取。

> **当前体验边界说明**：
> - 定时任务由服务端后台调度并由 Agent 执行，当前暂非 Android 系统级通知或锁屏推送；
> - 当前工具结果主要呈现为通用文本或按配置输出的受控摘要，专用的富交互卡片展示仍在逐步完善中。

## 未来规划

以下能力为明确规划中的演进方向，欢迎共同探索：

### 1. 深度浏览器集成（规划中）
单纯的公开网页抓取遇到登录页就寸步难行。真正的工作日常离不开需要本人身份认证的场景：例如查看个人云服务控制台的账单与资源状态、在项目管理平台中跟踪派发给自己的任务、或在私有知识库中检索文档并进行必要操作。

我们计划在用户明确授权与可控权限边界内，探索深度集成真正的浏览器环境，利用受限的个人登录会话协助处理真实任务。
*当前基础*：目前仅提供公开网页检索、网页抓取与 URL 监控，尚未集成浏览器；未来方案也绝不会在未经许可的情况下读取或导出账号密码凭据，且受目标网站反爬与安全策略限制，无法承诺所有网站或账号均可支持。

### 2. 开放平台与真实场景接入（规划中）
现实工作与生活依赖多样化的输入渠道。我们计划在明确的权限与系统边界内，逐步探索智能硬件（如随身录音设备、智能穿戴）、跨平台即时消息，以及在系统权限允许下的手机短信、电话、邮件等渠道的受控接入，将各方信息交由 Agent 统一梳理与协同处理。

*当前基础*：Pi Muse 现已提供公开的 HTTP/OpenAPI 与 AG-UI SSE 实时流接口作为协议基础；但目前尚未提供即插即用的硬件适配器、跨平台聚合收件箱或短信/电话连接模块。

## 快速开始

服务端运行需 **Node.js 24+** 与 **pnpm 12.10.1**，以及兼容 OpenAI Chat Completions 协议的模型服务。模型调用可能产生供应商费用。定时提醒与后台整理依赖服务端持续在线，建议部署于常开电脑或服务器。

1. **准备配置与启动服务**：获取代码后安装依赖，在 `.pi-muse/config.json` 中配置大模型接口凭据及服务访问密码（`server.accessKey`），启动服务端。具体命令与字段说明见 [快速上手指南](docs/getting-started.md)。
2. **下载移动客户端**：前往 [pi-muse-mobile Releases](https://github.com/yaotutu/pi-muse-mobile/releases) 下载最新 Android 安装包（APK）。
3. **连接并开始使用**：手机可通过局域网、安全虚拟组网（如 Tailscale）或 HTTPS 域名连接服务端，在客户端设置中填入服务器地址与 `server.accessKey` 即可开始对话。

## 安全与隐私

- **数据管理**：对话记录、用户画像、长期记忆与工作区文件存储在自部署的实例目录中，由你自行管理与备份；
- **模型通信**：服务端发起推理时，模型必要上下文会发送至你指定的大模型 API 服务商，请保管好服务端配置文件与访问密钥；
- **网络边界**：局域网使用必须配置 `server.accessKey`；公网远程访问严禁暴露裸 HTTP，请务必前置配置具备 HTTPS 证书的反向代理。
