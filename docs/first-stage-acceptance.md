# 第一阶段：能力说明修正与真实 Web 核心复验

> 日期：2026-10-11。结论：本阶段的 prompt 修正与核心复验完成；不是所有 P1-P4 场景的穷尽验收，也不代表移动端已验收。

## 1. 范围与代码改动

本阶段不开发新能力，不继续扩展架构，不迁移真实数据。

- `src/adapters/pi/system-prompt.ts`：删除没有长期记忆/后台任务的过时说明，准确描述显式记忆与定时任务。
- 记忆只响应明确的记住/忘掉请求；列出记忆依赖每轮注入的内容，不虚构 memory list 动作；禁止自动提取或保存密码、密钥等秘密。
- 定时任务支持一次性/每日创建、查询和取消，结果进入本会话，可能需要刷新/同步；不承诺邮件通知或实时推送。
- 文件工具仍只读且限定 workspace；不新增 shell、浏览器、邮件、日历权限。
- `tests/unit/pi-adapters.test.ts`：新增 prompt 与现有工具能力、安全边界一致的回归测试。

没有调整 agent loop、工具 allowlist、会话互斥锁、超时策略或数据格式。

- 专用数据目录：`/tmp/personal-bot-phase1.nnEGSa`，文件读取仅使用该目录 workspace 内的验收文档；不使用真实用户资料。

需要重验时创建新的临时 DATA_DIR；不要将本报告中的测试任务复制到真实数据目录。OpenMuse 仓库根目录启动命令为 `EXPO_PUBLIC_API_URL=http://localhost:8787 pnpm dev:web`。

## 5. 实际观察与边界

### 真实模型超时

忘掉乌龙茶轮中，memory 已返回 Forgot 1，随后模型未完成最终回复，在原配置 120 秒边界触发超时。OpenMuse 显示：

`Model response timed out; retry when the endpoint is available`

随后新轮成功回复超时后恢复正常，证明该场景未留下会话锁。此处只确认现象与恢复，不把原因未经诊断归结为供应商或本地实现。其他长轮在浏览器自动化 60/65 秒的等待窗口内未结束，不等同于服务端超时；后续分别观察完成或主动停止。

已成功的工具写入不会随最终文本超时或停止而回滚；失败提示不代表此前工具没有执行。维持简单优先、无自动重试，避免重复工具副作用。

### 停止后的旧话题延续

真实模型在长文被停止后的新轮中曾继续输出旧话题，并夹带已执行工具的确认。刷新后的新轮能完成，但回复不总是严格遵守只回复一句。本阶段记录为行为质量观察，未确认根因；不混入历史格式、上下文编辑或会话控制的额外改造。

### 客户端能力占位

原 OpenMuse 的 Worker offline 提示和 Gmail/Calendar/Computer 等入口仍可见；本项目没有实现这些能力，本轮不修改客户端占位 UI，也不将这些入口视为服务端已经支持。

- 生产日常 DATA_DIR、数据目录迁移、长期稳定性与性能压测。
