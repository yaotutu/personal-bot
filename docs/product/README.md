## 怎么维护

- 一个模块一份文档。后续有图标、启动画面等独立需求时，再增加对应文件，不提前建空文档。
- 模块文档记录：用途、已有能力、状态、所需资源、已有素材、待确认事项。
- 区分已确认的要求、讨论中的建议和实际完成的资源。建议不能直接记成定案，生成草稿也不能记成可交付成品。
- 具体清单只维护在模块文档中，索引不重复记录每项资源的进度。
- 这里只整理产品需求，不另写一套接口规范。协议以服务端契约及运行时 `/docs` 为准；业务实现以对应仓库为准。
- 本目录不改变素材归属：App 使用的素材仍放在客户端资源目录，README 展示图仍放在 `docs/assets/`。
