# 前端适配交接：会话技能、专属指令与隔离工作区

> 服务端基线：提交 `e37e544`（2026-10-18）。本文描述该提交的实际接口，不把设计稿或其他并行开发能力当作已交付接口。
>
> **关键结论：新增 5 个会话管理接口，不是新增一套文件管理 API。聊天增量请求和 AG-UI SSE 不变。**
>
> 本文限定 `e37e544` 的会话能力；`/api/events` 由后续独立提交 `473213f` 交付，不计入这里的5个接口。其客户端同步与重连规则以部署版本的 `/docs`、`/openapi.json` 为准，辅助说明见 `http-api-contract.md`。联调时先确认服务端部署版本，本文不是另一份 OpenAPI。

## 1. 本次产品变化

仍是一个 Agent，不是多 Agent。模型、SOUL/USER、长期记忆、目标和业务数据共享；会话维度新增/补齐以下能力：

| 能力 | 当前行为 | 前端影响 |
| --- | --- | --- |
| 会话技能开关 | 每个会话独立选择技能，生效值为会话覆盖 ?? 全局技能默认 | 新增会话技能设置，不能放到全局助手配置里 |
| 会话专属规则 | 每个会话有 INSTRUCTIONS.md，支持 HTTP 与对话自我修改 | 新增会话规则编辑器；打开时回读，避免覆盖对话中刚修改的内容 |
| 私有工作目录 | 所有会话含 local-main/task-* 各有独立私有文件区 | 现有读写工具请求不用变；文件路径显示需标清私有/共享 |
| 共享目录 | 用 shared/... 显式访问全局共享文件 | 不要把所有文件都标为共享，也不要拼服务端绝对路径 |
| 删除会话 | 普通会话可删，local-main 不可删；级联清理关联内容 | 新增删除确认与缓存清理，删除成功后刷新全局快照/审批 |
| 定时任务归属 | 在创建它的会话触发，结果写该会话历史 | 不要只刷新主会话或把所有提醒结果渲染进主会话 |
| 后台任务来源 | 有来源时继承该会话技能覆盖快照，结果通知回来源 | 页面创建时传 originThreadId；不要承诺共享父会话私有文件或指令 |

**关闭技能不等于删除业务数据，也不是关闭全局记忆/目标注入。**技能主要决定本会话的相关工具与技能说明装配。全局能力配置仍是上限：例如技能 write 开启，不代表绕过 `tools.writable.enabled` 或人工审批。

## 2. 接口增量总表

全部需要现有 `Authorization: Bearer <token>`。PUT 请求使用 `Content-Type: application/json`，路径中的 threadId 使用 `encodeURIComponent`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/threads/:threadId/skills | 当前会话技能列表、默认/生效开关和诊断 |
| PUT | /api/threads/:threadId/skills | 整份替换会话技能覆盖 |
| GET | /api/threads/:threadId/instructions | 读取该会话规则 |
| PUT | /api/threads/:threadId/instructions | 保存该会话完整规则 |
| DELETE | /api/threads/:threadId | 永久删除普通会话及其关联内容 |

已有 `GET /api/threads` 保留，返回 `{ threads: [{ id, updatedAt }] }`，没有新增 name/title/workspacePath 字段。`updatedAt` 仍代表聊天 JSONL 活动，不要把它当规则或技能修改版本。

本次**没有**新增：

- 工作区 CRUD、文件树/上传/下载/预览/移动文件 REST 接口。
- 任意目录选择、外部磁盘授权、修改会话文件根的接口。
- 会话重命名或显式 POST 创建会话接口。
- 安装/上传/编辑/删除技能的管理接口。
- REST 定时任务创建接口（对话仍走 schedule 工具）。

不要自行猜测 `/api/workspaces`、`/api/files` 或 `/api/tools/read` 等地址。要做可交互文件管理页，需另行补服务端契约，本轮不能只靠前端完成。

## 3. 会话设置：专属规则

### 3.1 建议入口

在会话标题/侧栏菜单中提供「会话设置」，包含：

- 专属规则：多行文本框、保存、清空。
- 技能：列表开关、加载诊断、恢复全部默认。
- 删除会话：仅普通会话可用，放到危险操作区。

UI 必须明确标注「只作用于当前会话；下一轮开始生效」，不要复用全局 SOUL/USER 编辑器来保存会话规则。

### 3.2 请求与响应

```http
GET /api/threads/email/instructions
```

```json
{
  "instructions": "你是邮件助手。回复简洁礼貌，结尾使用我的落款。"
}
```

未设置返回 `200 { "instructions": "" }`，不是404。GET 不要求已经聊天，也不会为缺失规则创建文件。

```http
PUT /api/threads/email/instructions
Content-Type: application/json
```

```json
{
  "instructions": "你是邮件助手。回复简洁礼貌，草稿结尾使用：张三。"
}
```

成功返回200，结构与GET相同。服务端去首尾空白，前端以返回内容更新编辑器的已保存基线。

清空使用：

```json
{ "instructions": "" }
```

### 3.3 实施要求

1. 上限20,000字符，不是20,000个token；空串允许。保存的是完整内容，不是追加片段。
2. 保存规则不修改聊天 revision，不需要前端手工修改 expectedRevision，也不需要重建聊天历史。
3. 当前正在运行的一轮不立即切换规则，下一轮使用新内容。推荐运行中展示该提示，不要承诺影响已发出的模型请求。
4. 模型可以通过 instructions 工具修改规则，因此每次打开设置、重新进入页面时回读。若设置页保持打开，可在本会话轮次完成后刷新；**有未保存草稿时不要静默覆盖草稿**。
5. 此接口没有规则专用 revision/ETag，不能做服务端CAS或可靠的多端冲突合并。避免后台自动保存覆盖；需要精确冲突控制时另行补契约。
6. 会话A的请求晚于切换到B才完成时，只更新A的缓存，不能填入B的编辑器。
7. 会话规则是模型指导，不是权限配置或严格输出格式验证器。不要提供「允许访问其他会话」之类无效选项。

## 4. 会话设置：技能开关

### 4.1 GET 返回

```http
GET /api/threads/email/skills
```

示例片段（真实列表以返回值为准，不应硬编码只含这两项）：

```json
{
  "skills": [
    {
      "name": "cron",
      "description": "安排未来提醒或周期性任务",
      "defaultEnabled": true,
      "enabled": false
    },
    {
      "name": "memory",
      "description": "显式记住或忘记信息",
      "defaultEnabled": true,
      "enabled": true
    }
  ],
  "diagnostics": []
}
```

- name 是稳定的技能键，不是工具名。UI可以提供中文展示名，但提交必须用返回的 name。
- enabled 是当前会话生效值，defaultEnabled 是技能默认值。
- diagnostics 在响应schema中可选，前端用 `diagnostics ?? []`；失败说明可折叠展示为纯文本，不让用户以为列表加载成功就代表所有技能正常。
- 用户技能可能随安装变化，列表必须动态渲染；不要通过数组下标或预设7个名称保存状态。

当前7个内置键为 cron、monitor、task、goal、memory、web、write。currentTime、read/grep/find/ls 不属于这些开关；天气仍由全局配置决定；instructions 在普通会话中不绑定技能开关。

### 4.2 PUT 是整份替换，不是 PATCH

```http
PUT /api/threads/email/skills
Content-Type: application/json
```

```json
{
  "overrides": {
    "cron": false,
    "web": true,
    "write": false
  }
}
```

成功返回200，结构与GET相同。

含义是：只对 cron/web/write 保存显式开关，**所有没有出现在 overrides 中的技能恢复跟随默认**。不要每次切换单项只发送 `{ overrides: { 当前技能: 值 } }`，否则会丢掉其他已配置覆盖。

未知技能名或非布尔值返回400。400时保留编辑草稿、刷新技能目录，不要无限重试原请求，也不要直接用老缓存中的已删除技能名再次提交。

全部恢复默认：

```json
{ "overrides": {} }
```

### 4.3 当前接口限制：不能精确回显三态

**GET只返回 defaultEnabled/enabled，不返回原始 overrides，也没有 isOverridden 字段。**当二者相等时，无法区分：

- 该技能没有覆盖，正在跟随默认；
- 用户显式设成了与默认相同的值。

因此本轮推荐：

- 第一版做**二态生效开关**，编辑器加载GET结果后保留全部技能当前生效值；保存时整份发送所有已列出的 name → enabled。明确这会把这些值固定为显式覆盖，而不是继续跟随未来默认值变化。
- 单独提供「恢复全部默认」按钮，发送空覆盖表。
- 不提供看似精确的「跟随默认 / 开 / 关」三态回显。若产品要求逐项继承状态，应先请服务端在GET/PUT响应补 `overrides` 或 `isOverridden`；前端不能靠 `enabled === defaultEnabled` 猜测。

保存后使用服务端响应回填；修改从下一轮装配生效，不影响另一会话，不取消已存在的后台/定时任务。

**技能开关只控制本会话对话能力，不是全局 REST 管理接口的授权开关。**例如本会话关闭 cron 仅使模型看不到 schedule，不意味着任务页API被禁用或已有提醒被删除。

## 5. 删除会话

### 5.1 入口与确认文案

- local-main 永久存在，不显示删除按钮；服务端删除它仍返回409。
- 其他会话显示删除按钮。建议确认文案：

> 删除后，本会话的聊天历史、专属规则、技能设置和私有文件将永久删除；关联定时任务及网页监控将删除，排队/运行中的后台任务将取消。共享文件、其他会话和全局数据不受影响。已完成的后台任务记录保留。此操作不可恢复。

不要只写「清空聊天」，也不要在确认框中伪造服务端未提供的级联数量预览。

### 5.2 请求响应

```http
DELETE /api/threads/email
```

无请求体。成功200：

```json
{
  "ok": true,
  "removed": {
    "jobs": 2,
    "monitors": 1,
    "tasks": 1
  }
}
```

- jobs/monitors 是删除数量。
- tasks 是本次取消的排队/运行任务数量，不代表删除了全部任务历史。
- 404表示目标会话不存在且没有需要清理的活跃绑定物；可提示「会话已不存在」并刷新列表。
- 409保护主会话；400表示非法ID；500不应显示成删除成功，应回读确认现状并展示错误。删除非事务，不承诺所有副作用在失败时回滚。

### 5.3 前端操作顺序

1. 确认后锁定该会话的发送、规则/技能保存和重复删除动作。
2. 调用DELETE。服务端会取消并等待该会话当前轮结束；不需要为能删除而额外提交stop。也可以复用已存在的显式stop，但不能仅在本地清空状态后假定删除完成。
3. 删除成功后，中止/释放该会话的本地流与请求，并使迟到响应失效。
4. 清理该会话历史/revision、草稿、规则、技能等缓存；当前正显示被删除会话时，切到 local-main 并GET同步其历史。
5. 刷新 `GET /api/threads`、`GET /api/agent`、`GET /api/actions/pending`，更新被删除的任务/监控与被取消的审批，不留旧卡片。
6. 不要在删除过程中/删除成功后对旧ID发PUT、自动重试发送或自动保存，这可能重新创建同名会话数据。重用同名ID视为全新会话，不能恢复本地旧历史到它。

## 6. 工作区与文件展示：不用新增聊天传参

### 6.1 客户端看到的逻辑路径

| 模型工具路径 | 作用范围 |
| --- | --- |
| drafts/reply.md | 当前会话的私有文件 |
| shared/templates/signature.txt | 全局共享文件 |

客户端不需要也不应拼接 `.pi-muse/workspace/threads/<id>/` 后发给工具；服务端根据当前thread装配根目录。run请求仍只提交原来的threadId、runId、expectedRevision、message，不接受 workspaceDir/systemPrompt/history 等附加字段。

建议聊天帮助与审批页：

- 将 `shared/...` 标注「共享文件」，其余普通相对路径标注「该会话私有文件」。
- 展示服务端返回的 threadId/runId 作为操作归属。
- 主会话不是文件管理员，不能浏览其他会话私有目录。
- 私有、共享写入都逐次审批；启用write技能不等于批准。
- 链接/越界被拒绝时显示实际错误，不包装成文件读取成功。
- 不根据“当前聊天窗口”重绑定另一会话的审批。pending列表可能包含其他会话操作。

### 6.2 不要因关闭 write 隐藏审批通道

技能变更不撤销已经发起的写操作。审批是全局独立通道，即使切换会话或本轮关闭write，也应继续正确展示仍有效的pending；批准/拒绝使用现有审批ID接口，不能从一张卡片推断已落盘成功。

## 7. 后台任务、定时任务与监控的适配

### 7.1 页面创建后台任务：传 originThreadId

已有接口支持该字段，不是新增端点：

```http
POST /api/agent/tasks
```

```json
{
  "prompt": "整理用户指定的资料并给出摘要",
  "title": "整理邮件资料",
  "originThreadId": "email"
}
```

- 从会话场景发起时，传用户当时选择的threadId；不要在异步提交结束时才从可能已切换的active读取。
- 不传时通知回主会话；要继承主会话技能覆盖，建议显式传 `local-main`，因为当前HTTP创建逻辑只在提供来源时执行覆盖快照。
- 后台任务是独立 `task-<id>` 会话，拥有自己的私有工作区；继承的是技能覆盖快照，**不自动继承父会话的INSTRUCTIONS.md或私有文件**。任务prompt必须自包含，共用材料要显式放共享区。
- retry复用已有任务快照。后台不装配 delegate_task/schedule/monitor，且当前不装配instructions工具；不要提供递归派任务的UI承诺。

### 7.2 页面创建监控：传通知来源

```http
POST /api/agent/monitors
```

```json
{
  "url": "https://example.com/news",
  "condition": "change",
  "title": "新闻变化",
  "intervalMinutes": 30,
  "originThreadId": "email"
}
```

来源用于通知投递和会话删除级联；监控不执行模型轮，不读取会话规则或技能快照。省略来源时默认主会话。

### 7.3 定时任务

- 对话 schedule 工具自动绑定本轮threadId，前端不新增 schedule 工具HTTP调用。
- 到时执行写入来源会话历史，不再统一进主会话；来源忙时顺延，不因此显示failed。
- 触发轮使用该会话当前规则与技能开关。关闭cron不自动取消已经创建的任务；取消仍走现有task control（target=job）。
- 本轮没有新增自动聊天历史推送；提醒/后台通知按既有刷新/后续同步读取，不能承诺手机通知或实时push。

### 7.4 列表仍是全局工作台，不要虚构按会话过滤

`GET /api/agent` 仍返回全局 tasks/goals/monitors/memories，不接新的thread过滤参数。

当前 **TaskDto（定时与后台）没有 originThreadId**，任务详情DTO也不暴露它，因此不能可靠做任务来源徽标、逐会话任务筛选或“跳转到来源会话”；不要从标题、task-id或当前active猜测。MonitorDto有可选originThreadId。若前端确实需要任务来源展示，服务端需另补response契约与presenter。

## 8. 聊天协议保持不变；新工具兼容兜底

聊天继续使用：

```json
{
  "threadId": "email",
  "runId": "本轮唯一ID",
  "expectedRevision": "GET历史返回的revision",
  "message": {
    "id": "新用户消息ID",
    "content": "帮我写一封邮件"
  }
}
```

- 不回传全量历史，不新增工作区/提示词字段。
- 409先刷新权威历史，恢复未接纳草稿；stop仍绑定threadId+runId。
- 新工具名 `instructions` 仍使用现有AG-UI TOOL_CALL事件，没有新增事件类型。未知工具名必须走通用renderer，不能报错或丢整轮消息。
- 可选增加instructions中文标签「会话指令」。无专用审批动作；它不是普通write文件审批卡。
- 默认工具展示可能hidden；summary下args可能只有 `{}`、result可能为受控摘要，不能要求工具卡里一定有完整新规则，更不能从空args推出“保存了空规则”。规则正文以GET instructions为准。
- 内部task-*不显示在普通会话侧栏；不要主动从任务ID拼一个用户会话入口。

## 9. 状态与错误处理

缓存至少按服务连接标识/账号 + threadId分组，历史、规则和技能草稿分别管理。切换会话时使用现有AbortController和请求代次校验，丢弃过期返回；编辑草稿不得因GET重试或其他会话结果被覆盖。

| 状态 | 处理 |
| --- | --- |
| 200 | 使用服务端返回值更新已保存状态；不要只改本地开关 |
| 400 | 展示参数错误；未知技能先刷新列表，保留编辑草稿 |
| 401 | 使用现有统一登录失效流程，不循环请求 |
| 404（DELETE） | 回读会话列表，可按“会话已不存在”收敛本地缓存 |
| 409（DELETE主会话/聊天冲突/任务控制） | 按端点语义分别处理，不能所有409都弹“历史冲突” |
| 500 | 如实提示失败；不伪装保存/删除成功，不自动覆盖损坏数据 |
| 503 | 服务关闭或模型未配置等按现有逻辑提示，避免自动生成重复副作用请求 |

ID校验：1–64字符，`^[a-zA-Z0-9][a-zA-Z0-9_-]*$`。中文展示名/服务端重命名字段尚未提供；不能把中文名直接当threadId提交。`local-main`主会话固定且不改名。

新会话仍可用合法ID进入并首次run时创建，或首次保存规则/技能时建立配置目录；GET规则/技能返回默认值不代表该会话已持久化创建成功。本地刚建未保存、未聊天的草稿会话可只在本地撤销。

## 10. 升级与旧数据清理

本实例已按用户要求清理旧业务数据，配置、签名密钥、人设及identity保留；当前可能返回只有local-main的空历史和空任务列表。

- 不迁移/重放客户端缓存的旧历史、旧revision或旧任务卡。
- 初次连接新版服务时从GET重新同步，清理失效的活动会话选择；目标ID不在列表中时回主会话，不后台自动发消息把旧ID重建。
- 不需要因为这次清理强制退出登录；token签名密钥保留，但仍按实际401处理。
- 其他部署不自动清数据；前端必须接受空态，也不能通过DELETE尝试“帮服务端迁移”。

## 11. 建议实施顺序与验收清单

### 第一批：本轮需要完成

- [ ] API层增加5个会话管理方法，复用Bearer/错误解析，支持DELETE。
- [ ] 会话设置：规则编辑、保存、清空、20k校验、下一轮生效提示。
- [ ] 会话技能：动态列表、生效开关、完整覆盖提交、全部恢复默认、diagnostics展示。
- [ ] 会话删除：主会话保护、不可恢复确认、成功后切主会话和缓存清理、刷新全局快照/审批。
- [ ] 后台任务/监控创建表单支持来源会话，提交originThreadId；全局工作台可明确选择主会话。
- [ ] instructions与未知工具通用渲染不中断，规则内容需要时回读管理接口。
- [ ] 文案区分私有/共享，保留跨会话审批归属与完整预览。

### 第二批：需要另行服务端契约后才能做

- [ ] 技能逐项三态继承的准确回显（响应补原始overrides或isOverridden）。
- [ ] 任务来源标签/跳转/按会话筛选（TaskDto补来源字段）。
- [ ] 文件管理页：列目录、上传/下载/预览等REST及权限/审批设计。
- [ ] 会话显示名/重命名、技能安装管理。
- [ ] `/api/events` 的独立版本联调，不纳入本交接的完成条件。

### 联调验收

1. A保存邮件规则，下一轮生效；B无该规则。对话工具修改后重新打开设置能看到最新内容。
2. A关闭web，下一轮工具不可用；B不受影响。保存另一个开关不丢A之前的设置，恢复全部默认有效。
3. 请求返回延迟时切换A→B，B的编辑器不被A结果覆盖；A未保存草稿有明确处理。
4. A读取/写入自己的相对文件，B同名文件不同；shared文件经批准可互通；越界与链接拒绝在卡片中诚实展示。
5. 主会话无删除入口；普通会话删除后列表、历史、规则、技能与审批状态一致，shared和全局记忆仍保留。
6. 删除失败/已不存在、非法ID、未知技能、401、500均不会显示伪成功。
7. 页面创建后台任务/监控的通知进入所选来源；后台任务不被描述为能自动读取父会话私有文件。
8. 空数据升级后不恢复旧消息/任务、不把已删除会话自动重建，原token未失效则继续可用。
