# Agent 文档编写指南

本文是 Pi Muse 手册和文档站的唯一维护规范，面向 Agent 与贡献者。文档站基于 VitePress 1.6.4 默认主题，Markdown 是唯一正文来源；必须提供简体中文与英文，维护单套当前源码版本，使用静态构建和本地全文搜索，不引入 CMS、动态 API 或多版本发布流程。

## Agent 执行顺序

1. 先确定读者和问题：用户要完成什么操作，或需要查清哪个概念、配置、故障。
2. 阅读相关现有页面及当前实现，优先修改已有主题；只有独立任务放进旧页会明显影响查找时才新建页面，不要求每个功能配一篇新文档。
3. 按下表确定归属，再选页面模板写正文；一个页面以一种写法为主，相关内容用链接连接，不复制正文。
4. 修改功能的同一任务内更新中英文对应页面、链接和必要导航；无文档影响时在交付中简要说明原因。
5. 按完成检查验证，交付时列出修改的页面、验证命令与结果、未验证限制；不把交付报告写进用户手册。

## 文档归属

以下均为仓库内路径。服务端与移动端共用一套产品手册，不在两端各维护副本；修改移动端功能时也要检查对应手册。

| 内容 | 位置 | 写作边界 |
| --- | --- | --- |
| 项目介绍与最短上手入口 | 根目录 README | 简明介绍并链接手册，不复制完整操作流程 |
| 安装、日常操作、配置、概念、排错 | 中文 `docs/manual/`，英文 `docs/manual/en/` | 面向使用者，两种语言均进入网页构建与搜索 |
| 架构、开发约束、测试与协作规则 | `docs/` 下已有对应工程文档 | 面向维护者，不进入手册；本文即属于此类 |
| 未实施方案与待办 | `docs/discussions/`、`docs/backlog.md` | 不能写成现有功能，不默认进入手册 |
| 历史实施与验收记录 | `docs/archive/` 或工作区既有证据目录 | 保留版本与证据边界，不作为当前操作步骤 |
| 渲染、导航与站点说明 | `docs-site/` | 只放站点配置与维护入口，不存第二套手册正文 |

## 中英文划分与同步

中英文是交付要求，不是可选译文。每个用户手册页面必须提供内容对应的两种语言，不接受只放语言菜单、英文摘要、待翻译占位页或复制中文充当英文。

| 语言 | 正文位置 | 访问路径 | 语言标识 |
| --- | --- | --- | --- |
| 简体中文，默认语言 | `docs/manual/<page>.md` | `/<page>.html`，首页 `/` | `zh-CN` |
| English | `docs/manual/en/<page>.md` | `/en/<page>.html`，首页 `/en/` | `en` |

- 中文沿用现有根目录与路径，不额外建立 `zh/` 副本；英文放在 `en/` 子目录。同一主题使用相同相对路径和文件名，例如 `docs/manual/getting-started.md` 对应 `docs/manual/en/getting-started.md`，首页均为各自的 `index.md`。不使用 `.en.md`、`.zh-CN.md` 等另一套手册命名方式。
- 新建、改名、移动或删除页面必须成对处理，修改既有内容也必须在同一任务内同步另一种语言。不确定译文时核对当前实现，不把错误或过期说明原样保留到另一语言，也不引入翻译状态库或运行时自动翻译服务。
- 两版的功能范围、操作前提、步骤、配置默认值、危险操作提醒、已知限制及发布/验收状态必须等价。表达可适应语言，不要求逐字翻译；不能省略关键条件或增加另一语言没有的能力承诺。
- 命令、协议名、工具名、配置键、文件路径及占位符保持一致；解释性注释和说明使用对应语言。英文说明中的中文界面名称可以保留原词并附英文解释，方便用户定位，不虚构尚不存在的英文产品界面。
- 各语言的页间链接指向本语言页面。H2 及更低层级的正文标题使用 VitePress 显式锚点，例如 `## 前提 {#prerequisites}` 与 `## Prerequisites {#prerequisites}`；同一章节中英文使用相同的、有意义的 ASCII kebab-case ID，且在页内唯一，避免默认语言切换携带不存在的翻译标题锚点。跨语言访问使用 VitePress 内置语言切换，按相同页面路径对应，不增加自定义路由或语言状态。
- `docs-site/.vitepress/config.mts` 分别配置两种语言的标题、简介、导航、侧栏与必要主题/搜索文案。两种语言均须可导航、可搜索；新增主题同时登记两侧导航，不以搜索或回退中文替代英文页面。
- 图片和其他无语言差异的素材共用 `docs/manual/assets/`，英文页用实际相对路径引用，不复制同一图片。含文字的图片需要对应语言版本或完整的本语言文字说明，图片替代文本也使用当前页面语言。
- 本节约束用户手册；根 README 继续遵守仓库已有的中英文文件约定。Agent 规则、架构规范和历史证据等内部文档不因此机械复制两套，也不进入用户手册构建。

## 职责与事实来源

- 用户指南唯一公开来源是 `docs/manual/`；`docs/` 下的架构、测试、设计、讨论和历史资料仅供 Agent/贡献者使用，不加入公开构建。本文也仅面向维护者，不混入用户指南导航。
- `docs/manual/` 每个主题在每种语言下只保留一份当前正文；中英文是配对译文，不按平台或历史版本再建副本。涉及 Android、浏览器、服务端等差异时在对应语言页面内说明，不做同义页面重复维护。
- HTTP/SSE 字段、路径、参数、错误和事件顺序的权威来源是当前源码的 `src/http/contracts/` 及运行实例自动生成的 `/docs`、`/openapi.json`。核对时注意实例版本，不用旧部署反推当前源码。手册只写使用语义和少量必要示例，不手写第二份 OpenAPI、请求参数表或完整接口清单。
- 文档只描述已实现能力。规划、待验收和已知限制应显式标注，不得用“支持”“已完成”或示例暗示未实现能力。
- 具体业务测试、真实后端和真实外部模型验收遵循[测试规范](testing.md)及根协作规则；文档构建和静态检查不能替代这些验收。

## 文件、链接与素材

- 新文件和目录名只使用 ASCII 小写 kebab-case，可用字符限于字母、数字、`-`、`_` 和扩展名点；禁止空格、中文和特殊字符。
- 正文、标题与图片替代文本使用所在语言目录对应的语言；每个页面正文只有一个 H1，标题层级从 H2 开始连续递增，不跳级、不把链接列表伪装成多级目录。
- 手册页面间链接必须使用实际存在的相对 `.md` 路径，如 `[快速上手](getting-started.md)`；不要链接构建产物或本机文件地址。站外链接优先用 `https://`，实际仅提供 HTTP 的服务按真实协议说明，不虚构 HTTPS 支持。不为尚不存在的文件预留可点击链接。
- 跨页锚点写为 `page.md#标题锚点`，必须核对实际渲染结果；修改标题时同步检查引用该标题的链接。手册不链接未参与构建的工程 Markdown 文件，需要指向工程源码或规范时使用对应仓库网页链接。
- 图片放在 `docs/manual/assets/`，在页面中按真实相对路径引用；没有图片时不创建空目录。截图只展示当前功能，不使用本机地址栏、终端、凭据或实例数据作为素材。
- 禁止把本机绝对路径、真实 AccessKey、模型 API key、token、真实 `.pi-muse/` 数据、会话内容或日志写入手册。示例使用 `<server-host>`、`<threadId>`、`your-model-api-key` 等无歧义占位符。

## 可用语法

使用标准 Markdown，并可用：

- 指定语言的 fenced code block，如 `sh`、`json`、`ts`、`text`；能识别的命令必须给语言，示意结构可用 `text`。
- 标准 Markdown 表格。
- VitePress 内置显式标题锚点 `{#section-id}`，用于中英文对应章节；不另加 HTML 锚点或自定义插件。
- VitePress 默认主题的 `tip`、`warning`、`danger` 容器。
- 可选 YAML frontmatter，仅保留 `title` 与 `description`。页面通常直接写 H1；只有搜索摘要或页面标题确有需要时才加 frontmatter，不添加布局、排序、组件等无关字段。

不要用 Vue、JS、HTML、自定义组件或主题插槽解决文档排版问题；这些语言的代码示例可以放在指定语言的代码块中。暂不使用需要额外插件的图表、扩展指令或 Markdown 语法；需要更强表达能力时先回到任务中确认范围，而不是在页面里堆实现。禁止为了绕过转义引入渲染脚本。

示例：

```md
::: warning 影响确认
此操作会删除该空间中的历史记录，且删除后无法恢复。请先确认空间名称，再执行。
:::
```

`${ENV_NAME}`、`<threadId>`、`password`、`http://<server-host>:12330` 等表达式必须放在反引号或 fenced code block 中，避免被当成正文或 Vue 模板解析。不要使用真实值替换占位符。

## 写作要求

- 标题直接回答读者问题，如“连接服务端”“配置说明”，不用“功能优化记录”“某模块开发总结”等实施记录标题。
- 正文先给用途与适用范围，再写必要细节。使用界面中真实可见的名称描述路径，如“设置 → 连接”；不要用内部组件名代替操作入口。
- 操作按执行顺序编号；命令前说明工作目录与前提，命令后说明预期结果。代码块中的可执行命令不加终端提示符，不把日志输出混在命令里。
- 必填项、可选项、默认值、生效时机和平台限制必须区分；不要让用户靠猜测补全关键步骤。示例可包含必需占位符，但要说明替换什么、在哪里获取，且不能要求用户把凭据粘贴到聊天或日志中。
- 操作指南回答“怎么做”，参考回答“可以填什么”，说明回答“为什么这样工作”，排错回答“出问题怎么办”。短小内容可以在同页分节，不为分类机械拆页。

## 页面模板

按读者任务选择模板，省略无实际内容的节；不要为了格式完整保留空节或编造排错项。

### 操作指南

用于安装、连接、启用功能和日常操作；快速上手也是操作指南，只保留最短成功路径。

```md
# 页面标题

一段说明：本页解决什么问题、适用于哪个平台或部署方式。

## 前提

- 已完成上游步骤，或链接到既有页面。
- 需要的运行环境、权限或配置。

## 步骤

1. 先说明用户要观察的状态或进入的路径。
2. 再给出命令或界面操作。
3. 每个可验证阶段写清预期结果。

## 预期结果

描述可见的最终状态和持久化效果。

## 排错

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 用户可复现的错误提示 | 先检查什么 | 如何修正 |
```

### 配置或查询参考

用于配置、选项、状态或限制的查询。配置事实要核对实际定义、校验和默认值，不凭字段名推断；HTTP 接口参数仍以自动生成的 API 文档为准。

```md
# 配置主题

说明配置位置、适用范围、修改后何时生效，以及前置操作的链接。

## 配置项

| 配置项 | 类型与可选值 | 必填与默认值 | 作用与限制 |
| --- | --- | --- | --- |
| `exampleOption` | 布尔值 | 可选，默认 `false` | 仅为模板占位，实际页面填写真实配置项 |

## 示例

给出最小有效示例，区分完整配置与需要合入现有配置的片段；不暗示覆盖整个文件。
```

### 概念或原理说明

用于解释空间、记忆、审批等概念及其边界；不必抄写源码结构或穷举实现细节。

```md
# 页面标题

说明本页覆盖的概念、适用范围和当前源码限制。

## 主题

- 每个小节回答一个明确问题。
- 表格用于对照字段、状态或取舍，不复制权威 API 契约。

> 适用范围变化、平台差异或未验证限制写在这里或对应小节内。
```

### 故障排查

从用户看到的现象出发，先检查低风险、常见原因，再说明如何处理；不能把删除数据、清空配置或重复发送写请求作为通用修复方案。

```md
# 故障主题

## 现象

描述可识别的错误提示或异常行为，以及发生在哪个平台、哪个步骤。

## 检查与处理

1. 检查可观察的状态，不预先断言故障原因。
2. 根据检查结果给出处理方式，并说明是否会修改数据。
3. 给出恢复成功的判断；仍无法定位时说明应收集哪些脱敏信息。
```

## 同步更新

开始任务时判断文档影响，收口前核对最终实现；需要更新的正文、链接与译文必须在同一任务内完成，不事后另开翻译或文档任务。按下面的场景决定更新位置，不要求每次代码提交都新增文档：

| 变更场景 | 文档动作 |
| --- | --- |
| 新增、删除或改变用户可用功能、操作入口、步骤、限制或错误处理方式 | 更新对应中英文手册；优先修改已有主题，删除失效说明 |
| 安装、启动、连接、升级流程或配置项、默认值、生效方式变化 | 更新上手或配置页面；README 的最短成功路径受影响时同步修改两版 README |
| 修复问题，只恢复手册已承诺的行为，操作与限制不变 | 不追加修复流水；手册原有绕行步骤或错误说明因此失效时才修订 |
| 纯样式、动画调整或内部重构，不影响使用方式 | 不强制更新用户手册；既有截图明显误导定位时更新截图，工程约束改变时更新对应内部规范 |
| HTTP/SSE 契约变化 | 更新契约源与自动生成文档；仅把影响用户操作的语义写入手册，不复制字段清单 |
| 新想法、未实现方案或暂缓事项 | 放入既有 discussions 或 backlog；不作为可用功能写入手册 |
| 测试结果、提交记录、临时排查或交接 | 放交付说明或已有验收证据目录；不写进用户手册、README 或 AGENTS.md |

不影响任何文档时，在交付中简述原因即可，不新增空文档、逐任务登记表或自动化管理系统。`AGENTS.md` 只保留必读入口，不累积上述规则、功能说明或完成记录。跨端任务由主 Agent 在派单时指定相关手册页与写集；执行者无对应仓库写权限时返回文档影响，由主 Agent 安排同任务内同步，不擅自越界。

- 涉及平台差异时写清 Android、服务端、浏览器容器等具体范围。手册默认描述当前源码，不把源码已有等同于已发布 APK；涉及发布差异时说明需核对对应发布版本。未实测的行为明确标为“未验证”，不能仅用“以当前源码为准”掩盖不确定性。
- 删除或替换功能时同步删除旧操作、旧字段和旧截图，不保留“历史兼容”双轨说明；历史资料只进入归档，不混入手册。
- 不在手册中硬编码测试数量、commit 哈希、验收时间、验收流水或会快速过时的依赖版本；确需版本边界时写可由用户核对的源码/发布版本。
- 写删除、重置、覆盖或清理步骤时必须说明影响范围、是否可恢复和需要用户确认的时机。不提供无提示的 destructive overwrite 命令。
- 新增源码参数示例时使用占位符，不复制真实配置；配置字段说明不替代源码校验和 OpenAPI。

## 导航与唯一链接

- 新增、删除或改名 `docs/manual/` 页面时，同步更新 `docs-site/.vitepress/config.mts` 的 `sidebar`；只有主栏目变化时才更新 `nav`，不把每个页面都塞进顶栏。页面发现不靠目录自动猜测。
- 同步修正所有站内 `.md` 引用和图片路径。旧页面被替代时删除正文并更新导航，不在新页旁边保留同义页。
- 一个主题在每种语言下只有一个入口页面；相关细节用相对链接串起来。除规定的中英文译文外，跨页重复时先选择唯一归属，再改链接，不为减少 diff 保留两份正文。

## 完成检查

文档改动完成后执行：

```sh
pnpm docs:build
git diff --check
```

- `pnpm docs:build` 必须通过，产物位于 `docs-site/.vitepress/dist`。提交前不保留调试产物；若构建生成被忽略文件，以 `git status` 和项目既有忽略规则为准。
- 修改 `docs-site/.vitepress/config.mts`、导航、主题、语言或搜索配置后，运行 `pnpm docs:dev` 或 `pnpm docs:preview`，并在桌面和手机宽度实际检查两种语言的导航、搜索、新页面可达性及同主题双向语言切换；`pnpm docs:preview` 使用回环地址 `http://127.0.0.1:4174/`。使用子路径部署时也须核对语言链接未跳出该子路径。
- 仅修改正文时至少完成构建和引用自查；配置或导航变更按上条做浏览器检查。
- 对照中英文目录检查页面一一对应，并检查内容等价、语言表述、标题层级、模板选择、图片路径、占位符、危险操作说明和未验证限制。不能只以构建成功认定翻译完整。文档-only 变更不运行业务测试；涉及业务行为时另行按[测试规范](testing.md)完成真实后端和外部模型验收。
