# Activity 执行活动：业务规则讨论

记录日期：2026-10-18。

**状态：纳入、登记与完成标准已获用户确认；接口和其余生命周期细节仍在逐项讨论，尚未授权实施。** 本文是需求讨论记录，不是已提供的接口契约。实施时必须同步契约源、自动生成文档和测试。

## 已确认：什么进入活动记录

- 动态用于跟踪用户交办的一项工作，不是聊天历史的副本，不因每次用户发消息就创建记录。
- 由当前主 Agent 理解完整对话，决定正常交流还是开始推进一项工作；不是额外运行一个分类模型，也不是后端解析回复来猜。
- 不穷举工作类型，不以关键词、耗时、工具次数或是否调用 subagent 机械分类。
- pi 不提供“普通对话”自动标记。没有登记仅表示没有活动记录，不能证明模型一定正确分类，也可能漏调；不承诺零误判。

## 已确认：登记工具的职责与规则

工具名称和参数尚未定稿，以下是必须表达给 Agent 的语义规则：

> 登记一项正在为用户执行的工作，让用户能跟踪它的进展和结果。登记本身不执行工作、不启动后台任务、不调用子代理，也不扩大权限。
>
> 当用户已经把一个目标交给你完成，而你决定开始实际推进时，先登记活动，说明要做什么、完成后交付什么，再继续执行。
>
> 普通交流、知识解释、澄清问题、需求讨论、方案审阅或简单查询不登记。不要为了调用了某个工具就登记；内部准备、读取记忆、每次工具调用或每个子代理不各自登记。相同工作已经登记时，更新原活动，不重复创建。

用于校准而非穷举的例子：

- “研究这个方案是否合理，先讨论，不要实施”：讨论，不登记。
- “方案确定了，现在去实施并验证”：开始工作，登记。
- “调研 Pi 生态圈，整理结论给我”：交办工作，登记。
- “刚才说的 Pi 生态圈是什么意思”：解释，不登记。

是否登记与是否使用 subagent 分开：主 Agent 可以自己执行，也可以委派；不恢复已经移除的 delegate_task 或业务 worker 队列。

## 已确认：什么时候完成

- 一条活动覆盖整项交办目标。搜索网页、阅读资料、处理文件、编辑成果、等待审批及调用子代理，均是所属活动的执行过程，不分别创建业务活动。
- 达成目标所需的必要步骤全部完成、结果已交付后，才由主 Agent 明确登记完成。
- 单个工具结束、子代理返回或一轮模型回复结束，都不能自动等同于活动完成。
- 例如“调研 X 并整理文档”：收集资料、阅读、整理和要求的文档操作完成，并交付结果后才算完成。PDF 只是用户举例，不代表已经新增 PDF 工具或其他执行能力。
