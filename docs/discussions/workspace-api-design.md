## 二、全局 SSE 的已确认边界

- SSE 是服务端向外单向推送展示数据的通道，不接收批准、拒绝、停止等操作命令；用户操作通过独立 HTTP 接口提交。
- 当前审批直接推完整内容与必要修改预览，处理、过期或取消后直接推最新状态；不能要求收到空通知后再查询一次才能看到审批。
- 连接或重连时提供当前状态、仍在进行的活动和完整待审批项，后续推送最新变化，不要求补发全部历史。
- Agent 当前活动与其所属会话、运行和子代理关联；复用 Activity 的事实与契约，不建立第二份活动状态或历史存储，不把每次工具调用或子代理另建成一项工作。
- 任务状态、目标更新属于实时状态推送方向；相应领域接口尚未讨论完，不在本轮记录中提前定义它们的事件、字段或操作语义。
- 记忆属于底层数据，通过独立接口查询和管理，不广播记忆变化通知。
- 全局状态流与聊天文字流分开；通知连接断开不取消正在执行的聊天或子代理。不借本次调整改变现有聊天流的取消协议。
- 本通道不承担手机锁屏系统推送，不增加可靠事件日志、durable execution、断点续跑或模型/工具自动重试。

## 三、接口职责与候选命名

这些命名是后续实施的设计基线，不代表当前已提供接口；最终字段、错误码及事件必须落入契约源后自动生成文档。

| 候选接口 | 职责 |
| --- | --- |
| `GET /api/events` | 当前状态与后续变化的单向直接推送 |
| `GET /api/activities` | 查询活动列表，按需分页查看历史 |
| `GET /api/activities/:id` | 查询同一活动的概览与逐步明细 |
| `POST /api/approvals/:id/decision` | 提交用户批准或拒绝，不等同于实际执行 |
| `GET /api/approvals` | 分页读取已处理/失效审批摘要，不混入 pending 或完整预览 |
| `GET /api/approvals/:id` | 只读查看当次完整审批预览、决定及已知执行结果 |

登记与完成 Activity 的工具名称、字段、跨轮关联、等待/失败/停止/重启等实现细节，以已确认的业务规则和项目安全约束为依据，在实施设计中具体化。不能把未完成工作标成成功，也不能为处理这些边界新增自动续跑系统。
