# 待实施需求池

这里统一记录已经讨论、但尚未实施的需求。当前实现以源码为准，验收结论以实际执行结果及对应版本报告为准；本文件不是“已经支持”的功能清单。

## 使用约定

- **讨论不等于开工**。用户认可方案，也不代表立即授权实施；明确要求“先记录、晚点做”的需求保持待实施。
- 后续讨论形成新需求时，先在这里登记；较详细的方案放 `docs/discussions/`，本页保留入口与状态。
- 区分“讨论中”和“方案认可、暂缓实施”，不要把助手建议记成用户定论。
- 开始实施、变更范围或完成验收时更新状态；完成后移出待实施清单，需要保留的版本验收记录放 `docs/archive/`，不另建交接文档。
- 不因为登记需求自动创建定时任务、启动后台处理或修改正式数据。

- **目标：** 每 2 小时对开启的会话做后台整理：读取游标之后的新消息（带重叠上下文），把长期信息写入 `USER.md`、`SOUL.md`、会话 `INSTRUCTIONS.md` 或 `memory.json`；拿不准的不写，交用户决定。
- **方案：** [Dream 后台记忆整理](discussions/dream-memory.md)。

- **核心边界：** 不重写 pi 压缩或 agent loop；不新增 `MEMORY.md`；不阻塞聊天、不扩大普通文件工具权限、不自动重试模型或工具；写入前比对版本，不覆盖用户刚改的内容。

### REQ-002 · 重置当前会话（保留记忆与工作区）

- **记录日期：** 2026-10-18。
- **状态：** 用户已确认核心方案，暂缓实施；未开工，具体交互与执行细节在实施前细化。
- **已确认语义：** 这是“重置当前会话”，不是“新建/切换到另一个会话”。用于用户主动清空上下文，或当前上下文出问题无法继续时；不作为日常创建新会话的入口。
- **需求：** 清空当前会话的模型上下文，保留原工作区、已持久化记忆、会话规则与工作成果，继续使用当前会话的工作环境，不要求用户重新配置或复制一份工作区。
- **实施前需细化：** 旧历史如何保留和查看、重置时运行及审批如何收尾、后台任务通知如何衔接。助手曾建议不继承坏上下文、恢复不依赖模型先总结；这些细节尚未单独定稿。
- **边界：** 重置上下文不等于修复磁盘损坏、无效凭据或扩展故障；不把本需求扩展为 durable execution 或自动重跑业务操作。

### REQ-004 · 审批决定、执行结果与历史查询

- **记录日期：** 2026-10-18。
- **状态：** 已实施（`GET /api/approvals`、`GET /api/approvals/pending`、`GET /api/approvals/:id`、`POST /api/approvals/:id/decision`，授权与执行回执分离，完整预览长期保留）。接口以 `/docs` 与 `/openapi.json` 为准。
- **已确认语义：** SSE 直接推待审批内容，用户通过独立HTTP接口批准/拒绝。批准只授权该次操作，不代表执行成功；拒绝不自动使整项activity失败；实际结果由工具执行确认后更新活动步骤和进展。
- **历史列表：** 分页读取已批准/拒绝/过期/取消的摘要，不含pending和整份文件预览；包含操作、状态、时间及来源会话/activity，完整内容按单项详情读取。审批决定与执行结果分开。
- **单项详情：** 返回当次完整预览、操作/目标、审批状态/时间与来源，执行结果按真实事实单独提供；不以当前文件替代历史预览，不因读取详情重新执行或恢复旧授权。
- **历史留存：** 历史记录及当次完整修改预览长期保留，暂不增加按时间自动清理，不以分页或数量上限静默裁剪；不改变待审批授权现有有效期。
- **安全边界：** 保留完整预览、逐次授权、版本绑定、过期与取消保护；Agent不能自行批准。
- **实施依据：** [审批接口](discussions/approvals.md)。决定、历史和详情的接口职责已确认，字段、幂等、冲突、分页与结果编码由实施方按规范确定，不作为当前API。

### REQ-005 · 完整浏览器能力（用户可操作 + Agent 可操作）

- **记录日期：** 2026-10-18。
- **状态：** 调研完成，推荐方案已给出，待用户确认后实施；未开工。
- **目标：** 提供一个真正可用的完整浏览器：有连续画面、可完整操作、能输入地址、登录态可保留；Agent 在需要时能操作同一个浏览器。
- **推荐方案：** 服务端 Chromium（`playwright-core` + 系统 Chrome）＋ CDP `Page.startScreencast` 帧流（WS 二进制）＋ `Input.*` 输入转发；用户与 Agent 共用同一实例与同一持久化 profile。
- **实测依据：** 1280×800 JPEG q60 下 34.5fps、0.23MB/s，帧间隔 p50 21ms；点击往返 34–53ms，中文输入 46ms；后台标签零帧；`Browser.close` 后登录态完整保留，SIGTERM 会丢 cookie，需优雅关闭＋storageState 快照兜底。
- **关键边界：** 不暴露任意 JS 执行给模型；页面内容不可信；不向密码框输入、不读 cookie/localStorage；沿用 `allowPrivateTargets` 语义并禁止访问自身控制面；敏感域动作可复用现有审批。
- **讨论记录：** [完整浏览器能力调研与方案](discussions/browser.md)。本地/远程优先级、profile 策略、工具粒度、WS 契约等尚未定稿，不作为当前实现。
