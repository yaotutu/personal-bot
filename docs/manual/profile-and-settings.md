# 资料与设置

本页说明手机客户端中的助手与用户资料、常用外观、服务器连接、真实浏览器入口和 Android 应用更新。操作入口按当前移动端与服务端源码核对；源码能力不自动等于某个已发布 APK，实际界面以你安装的 Release 为准。

## 前提 {#prerequisites}

- 已按[快速上手](getting-started.md#connect-mobile-client)完成首次连接；未连接时仍可使用主题和应用更新，但资料、记忆和 Dream 功能不可用。
- 助手与用户资料保存在服务端，全部空间共用；主题偏好只保存在本机。

## 助手与用户资料 {#assistant-and-user-profile}

1. 进入底部「设置」→「助手与个人资料」→「助手与用户资料」。页面读取成功后显示「助手设置」和「人设与资料」两组内容。
2. 资料草稿只保留在当前工作区连接内；关闭面板或退到后台不会主动清空，但退出应用、换服务器等导致工作区重建后会丢弃。

### 保存助手设置 {#save-assistant-settings}

1. 在「助手设置」中输入「助手名字」。去除首尾空白后需要 1–80 字符。
2. 选择「温暖」「简洁」或「周到」语气。如果服务端返回了当前客户端不认识的旧语气值，页面会显示原值并要求重新选择受支持值。
3. 点击「保存助手设置」。成功后显示「身份已保存」，修改标记消失。

名字和语气是全局设置，保存后从下一轮对话开始生效，不修改已生成历史。主空间顶栏会显示助手名字；非主空间顶栏仍显示空间 ID。

### 保存人设与资料 {#save-soul-and-user}

1. 在「SOUL · 助手人设」中填写希望助手具备的性格与工作方式；在「USER · 用户资料」中填写希望助手了解的背景与偏好。
2. 两段文本各最多 20000 字符，可以留空。点击「保存人设与资料」时，两个字段作为同一次资料保存提交；把某一段清空并保存即清空该段。
3. 成功后显示「人设已保存」。SOUL/USER 从下一轮对话开始全局生效。
4. 点击「取消助手设置修改」或「取消人设与资料修改」，可分别放弃对应草稿并回到最后一次成功读取或保存的值。

助手设置和 SOUL/USER 是不同保存入口；保存其中一组不会自动保存另一组。SOUL/USER 请求内部按顺序保存两段文本，极端情况下可能一段已保存而另一段失败；保存失败或结果未明时保留草稿，先刷新核对，再决定是否显式重新保存。

每段资料内容以自身最后一次成功保存为准，客户端不自动合并不同草稿，也不提供版本冲突保护。SOUL/USER 会进入后续全局模型上下文并发送给服务端配置的外部模型服务；不要填写凭据或不愿提供给该服务的内容。这些自定义指令不能扩大工具权限、访问范围或绕过文件审批。

## 外观主题 {#appearance}

1. 进入底部「设置」→「外观」。
2. 在「经典蓝白」「晨光白」「深夜黑」中选择一项。选择后界面立即切换，并尝试把主题偏好保存到本机。
3. 保存失败时界面仍显示新主题，但会提示主题未能保存到本机；重新选择同主题或其他主题可再次尝试保存。
4. 点击顶栏或设置页右上角的亮暗快捷按钮时，从深色回到最近选择的浅色主题；前往深色则使用「深夜黑」。

主题偏好与服务器连接、AccessKey、Token 和业务数据分开保存；换服务器或重新认证不会清除主题。该设置只影响本机界面。

## 服务器连接 {#server-connection}

首次填写地址、密钥和连接步骤见[快速上手](getting-started.md#connect-mobile-client)。此后可按下面方式维护：

1. 进入底部「设置」→「连接与设备」→「服务器连接」。
2. 修改「服务器地址」或「访问密钥」后点击「测试连接」。测试通过只表示当前草稿可访问，尚未保存。
3. 同一地址重新认证时，可填写新的访问密钥并测试，然后点击「重新认证」。留空测试同一地址会沿用当前 Token。
4. 改为其他服务器地址时，先阅读「更换服务器前请确认」，点击「继续保存」，再按按钮提示保存新地址。
5. 服务器暂时不可用时打开本面板，点击「重试连接」；本机连接配置读取失败时点击「重新加载」。

换服会要求确认，并让客户端放弃旧地址的本地业务缓存和旧凭据；该操作不会删除任何远端服务器数据。已保存的真实浏览器地址和本机主题偏好会保留。若只保存地址、稍后认证，客户端不会保存 Token；测试或连接成功后保存的是服务端签发的长期 Token，不保存明文 AccessKey。

当前应用没有「退出登录」或「注销服务器」按钮。关闭连接面板只清空本次输入的访问密钥；退到后台或退出应用只会暂停网络请求，本机仍保留服务器地址和 Token，下次可继续使用。Token 在服务重启后仍有效；服务端更换或清除 `server.accessKey` 后会被拒绝，此时客户端会提示需要重新认证。

## 真实浏览器 {#real-browser}

1. 进入底部「设置」→「连接与设备」→「服务器连接」，在「真实浏览器」中填写完整的 noVNC 页面地址，例如 `https://browser.example.com/vnc.html`。地址只支持 HTTP(S)，不能在主机名前携带 HTTP 账号或密码；启用 VNC 密码时，按部署说明填写完整入口。留空保存可清除配置。
2. 点击「保存浏览器地址」。保存前需要已有服务器地址；客户端不会从 API 地址推测 noVNC 主机、端口或路径。
3. 返回设置页，点击「连接与设备」→「真实浏览器」。客户端会通过系统浏览器打开该地址，不会在应用内内嵌浏览器。

部署 noVNC、默认端口、移动页面和安全边界见[真实浏览器 Docker 与 noVNC 使用说明](browser-docker.md)。noVNC 入口不受 Pi Muse API AccessKey 保护；默认部署未设置 VNC 密码时，能访问该地址的人可能看到并操作远端桌面，不要把它暴露到不可信网络。

## Android 应用更新 {#android-updates}

1. 进入底部「设置」→「连接与设备」→「应用更新」。应用在前台启动时和每小时会自动检查一次；也可点击「立即检查更新」或「再次检查」。
2. 检查只读取官方 GitHub 仓库的正式 Release，且只接受唯一的 `app-release.apk`；预发布、draft 和其他文件不会作为更新包。
3. 发现更高版本后应用会显示当前版本、目标版本和大小，并开始下载。下载可取消、可重试，过程中可继续使用应用；下载可能消耗移动流量。
4. 下载完成后客户端会打开 Android 系统安装器。首次可能需要按系统提示允许 Pi Muse 安装未知应用，最后仍需在系统界面确认安装；打开安装器不代表升级已完成。
5. 如果检查失败，页面提供官方 APK 地址和「重新检查」。可打开 [pi-muse-mobile Releases](https://github.com/yaotutu/pi-muse-mobile/releases) 手动下载并按系统提示安装。

当前更新路径只支持 Android 独立安装包，不是 Expo OTA。iOS、Web 预览和 Expo Go 会显示当前环境不支持 APK 更新；无法读取当前安装包版本时也会提示改用正式 APK 手动处理。用户取消安装后，若系统仍保留缓存包，可点击「继续安装」；缓存被系统清理后需要重新下载。

## 常见问题 {#troubleshooting}

| 现象 | 检查与处理 |
| --- | --- |
| 资料页显示最后读取值或保存结果未明 | 点击「刷新」核对服务端值；确认后可再次显式保存，客户端不会自动重试。 |
| 主题已切换但提示未保存 | 本机存储暂时失败；重新选择主题以重试保存，界面当前显示不受影响。 |
| 服务器状态为需要重新认证 | 打开「服务器连接」，输入当前 AccessKey 并测试，再点击「重新认证」。 |
| 无法打开真实浏览器 | 先确认已保存完整 noVNC 地址，再检查手机系统浏览器能否访问该地址；入口不是内嵌浏览器。 |
| 应用更新检查失败 | 稍后重试，或从官方 Releases 手动下载 APK；检查更新不依赖 Pi Muse 业务服务器。 |
