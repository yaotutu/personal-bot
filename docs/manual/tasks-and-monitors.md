# 定时任务、网页监控与活动历史

本页说明当前移动客户端中的定时任务、网页监控与活动历史入口。底部导航现在是「新闻」，不再提供旧的「任务」汇总页；任务和监控仍保留服务端能力，但当前客户端主要通过聊天中的 `schedule`、`monitor` 工具管理。内容按当前服务端与移动端源码核对，不等于某个已发布 APK 的实际界面。

## 用途与范围 {#purpose-and-scope}

- **定时任务**：到点后把任务内容作为一条用户消息投递到来源空间的当前会话，触发真实模型执行。
- **网页监控**：服务端周期抓取一个公网 HTTP(S) 页面，在内容变化或关键词从未命中变为命中时通知来源空间。
- **活动历史**：模型在真实执行中显式登记的复合工作时间线；它不是全部聊天、全部工具调用或全部后台通知的汇总。

聊天中的 `schedule` 与 `monitor` 工具只列出和控制当前空间记录，不接受跨空间目标。服务端仍保留 REST 管理能力供其他受信客户端或后续界面使用，但当前移动端没有旧的底部任务页、全部空间汇总、任务编辑表单或独立监控管理页。

## 前提 {#prerequisites}

- 手机已按[快速上手](getting-started.md#connect-mobile-client)连接真实服务端，并使用与当前源码匹配的 Android 客户端。
- 服务器需保持运行。默认每 30 秒扫描定时任务、每 60 秒扫描网页监控；服务停止期间过期的一次性任务不会补跑。
- 创建定时任务依赖当前空间的 `cron` 技能，创建网页监控依赖 `monitor` 技能；若被关闭，先在空间设置中恢复。
- 到点任务和监控检查都可能访问外部网络并产生模型费用。网页监控只访问公网 HTTP(S)，抓取内容是不可信数据。

## 查看活动历史 {#view-activity-history}

1. 在聊天页打开当前空间的会话面板。
2. 进入「历史」页查看该空间的活动列表。
3. 如列表已有活动，可按执行中、等待审批、等待补充信息、等待明确继续、已完成、执行失败、已停止或执行中断筛选。
4. 点击活动查看目标、交付、进展、结果与安全步骤投影。步骤不包含模型内部思维或原始工具载荷。
5. 有更多记录时加载下一页。列表按创建时间从新到旧排列；重新进入页面、切换筛选、应用回到前台或收到相关状态变化后会回读。

当前客户端只在会话面板中提供当前空间的活动历史，没有旧任务页的「全部空间」范围切换。普通问答、解释、澄清和简单查询通常不会生成活动。`awaiting_continuation` 表示上一轮已结束但工作未完成，需要回聊天页明确提出继续。

## 创建与控制定时任务 {#scheduled-jobs}

1. 在聊天页确认当前空间。任务绑定这个来源空间；重置空间会话默认保留任务并转绑新会话，删除空间会删除任务。
2. 在消息中说明任务内容与一次性或每日时间。例如：“创建每天 09:00 的定时任务，总结今天的待办”或“创建一次性任务，明天上海时间 09:00 提醒我复核清单”。
3. 等待模型实际调用 `schedule` 工具。成功结果应包含任务 ID、状态与下次执行时间；只有自然语言承诺不算已排期。
4. 需要查看或控制时，继续在当前空间聊天中让模型调用 `schedule` 工具。工具只能列出、暂停、恢复、取消、删除或重试当前空间的任务。

一次性时间必须带明确时区。每日任务使用 `HH:mm`，按 `/api/health` 返回的服务端本地时区解释，而不是手机时区。暂停只停止后续调度；取消不是停止正在执行的聊天轮次；立即重试只用于失败任务，并会启动一次真实模型执行，不会自动重复提交。

## 创建与控制网页监控 {#web-monitors}

1. 在聊天页确认当前空间。监控通知投递到这个来源空间；删除空间会删除绑定监控。
2. 在消息中提供公网 HTTP(S) 链接、触发条件和检查间隔。例如：“监控 `https://example.com/product`，出现‘补货’就通知我，每 5 分钟检查一次。”
3. 触发条件只有两种：`change` 表示内容指纹变化；`contains` 表示指定关键词从未命中变为命中，必须提供关键词。
4. 等待模型实际调用 `monitor` 工具，再通过当前空间的工具结果核对状态、条件、累计检查和来源空间。
5. 查看、暂停、恢复、停止或删除也通过当前空间的 `monitor` 工具完成。停止是终态，不能恢复；要继续监控需重新创建。

`change` 的首次检查只建立基线，不通知；之后内容指纹变化才通知。`contains` 持续命中不会重复通知，只有未命中转命中才通知。暂停或停止只控制后续检查，不会立即发起一次检查，也不会删除已经观察到的事实。

## 可见结果 {#visible-results}

- 定时任务到期后，来源空间聊天会出现以「⏰ [定时任务]」开头的用户消息并进入真实模型执行。
- 网页监控命中后，来源空间会收到以「📡 [监控]」开头的通知。
- 活动状态和步骤随真实执行更新；失败、拒绝、取消、过期和中断会保留，不会伪装成成功。

默认扫描周期意味着实际执行可能稍晚。若工具结果显示结果未明，先重新读取当前状态，不要自动重发写操作。

## 限制与排错 {#limits-and-troubleshooting}

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 任务没有到点执行 | 服务器是否常开、来源空间是否正在运行、扫描是否稍晚 | 等待下一轮扫描；正在运行的会话会让到期任务等待。停机错过的一次性任务不会补跑。 |
| 重启后一次性任务没有执行 | 任务是否已过期 | 到期任务不会补跑；需要时新建。每日任务会重算下一次未来时间。 |
| 任务失败 | 最近执行结果和错误状态 | 失败不会自动重跑；核对影响后通过当前空间工具手动重试或新建。 |
| 每日时间不符合预期 | `/api/health` 返回的服务端时区 | 按服务端时区填写 `HH:mm`，不要按手机时区换算。 |
| 监控不通知 | 条件、最近检查、抓取错误和服务状态 | `change` 首检和未变化不通知；`contains` 持续命中不重复通知。 |
| 监控抓取失败 | URL 是否为公网 HTTP(S)、页面是否可访问、Web 工具是否启用 | 修正链接或稍后重试；失败状态保留到下一次成功检查。 |
| 找不到旧任务汇总页 | 底部导航已由「新闻」替代 | 任务和监控通过当前空间聊天工具管理，活动历史在会话面板的「历史」页。 |
| 操作结果未明 | 工具结果和当前空间回读状态 | 先核对记录是否仍存在及当前状态，再决定是否重试；不自动重发。 |

删除空间会删除该空间的活动历史、绑定定时任务和监控，且不可恢复。仅清空聊天时使用会话重置，并按确认卡片决定是否同时清理任务和监控。
