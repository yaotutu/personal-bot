# 定时任务、网页监控与活动历史

本页说明如何创建和管理 Pi Muse 的定时任务与网页监控，以及如何查看模型显式登记的活动历史。内容按当前服务端与移动端源码核对；源码核对不等于本轮实际业务运行或发布 APK 实测，已安装 Release 的可用功能以该版本界面和发布说明为准。

## 用途与范围 {#purpose-and-scope}

- **定时任务**：到点后把任务内容作为一条用户消息投递到来源空间的当前会话，触发真实模型执行；适合一次提醒或每天固定时间执行的工作。
- **网页监控**：服务端周期抓取一个公网 HTTP(S) 页面，在内容变化或关键词从“未命中”变为“命中”时通知来源空间。
- **活动历史**：模型在真实执行中显式登记的复合工作与长期工作的时间线；它不是所有聊天记录、所有工具调用或所有后台通知的汇总。

三者入口都在底部「任务」页。会话面板的「历史」页也显示当前空间的活动历史，但默认不提供切换全部空间的范围按钮。
聊天中的 `schedule` 与 `monitor` 工具只列出和控制当前空间的记录；即使知道其他空间任务的完整 ID，也会得到“未找到”且不会改变该记录。底部「任务」页的 REST 管理仍支持「全部空间」汇总和显式跨空间管理。

## 前提 {#prerequisites}

- 手机已按[快速上手](getting-started.md#connect-mobile-client)连接真实服务端，并使用当前源码对应的 Android 客户端。
- 服务器需保持运行。默认每 30 秒扫描定时任务、每 60 秒扫描网页监控；服务停止期间过期的一次性任务不会补跑，每日任务会重算下一次未来时间。
- 在聊天中创建定时任务依赖当前空间的 `cron` 技能，创建网页监控依赖 `monitor` 技能；默认内置技能开启，若被关闭需先在空间设置中恢复。
- 定时任务到点会调用配置的外部模型，可能继续调用工具、触发文件审批并产生模型费用。网页监控依赖 Web 工具启用，并只访问公网 HTTP(S) 内容。

## 查看活动历史 {#view-activity-history}

1. 点击底部「任务」页，保持「任务内容」中的「活动历史」选中。
2. 用「全部空间」或「当前空间」选择范围。从底部「任务」页进入时默认是「全部空间」。
3. 如列表已有活动，可用「全部」「执行中」「等待审批」「等待补充信息」「等待明确继续」「已完成」「执行失败」「已停止」「执行中断」筛选状态。
4. 点击活动查看目标、交付、进展、结果和执行步骤。步骤是服务端记录的安全投影，包含模型、工具、子代理、人工审批与文件提交等事件，不包含模型内部思维或原始工具载荷。
5. 有更多历史时点击「加载更多」。列表固定按创建时间从新到旧排列；本页没有单独的手动刷新按钮，重新进入页面、切换筛选、应用回到前台或收到相关状态变化后会回读。

普通问答、解释、澄清和简单查询通常不会生成活动。`awaiting_continuation` 表示上一轮执行已结束但工作未完成，需要回聊天页明确提出继续；服务重启或中断可能显示「执行中断」。活动随来源空间删除而删除。

## 创建定时任务 {#create-scheduled-jobs}

1. 在聊天页先打开空间侧栏确认当前空间。任务会绑定这个来源空间；之后空间重置会话时默认保留任务并转绑新会话，删除空间则会删除任务。
2. 在消息中直接说明任务内容、一次性时间或每日时间。例如：“创建每天 09:00 的定时任务，总结今天的待办”或“创建一次性任务，明天上海时间 09:00 提醒我复核清单”。
3. 发送后等待模型调用 `schedule` 工具。创建成功时工具结果会显示完整任务 ID 和下次执行时间；之后在聊天中取消时也应使用这个完整 ID。
4. 到底部「任务」→「定时任务」核对状态、时间、来源空间和下次执行。

当前移动端没有“新建定时任务”表单。如果模型只回复文字而没有调用工具，请明确要求它创建定时任务，或先检查 `cron` 技能是否启用；不要把聊天中的自然语言承诺当作已排期。

一次性时间必须带明确时区；在移动端编辑时，应用按手机本地日期和时间生成带偏移的时间戳。每日任务只填 `HH:mm`，按服务端本地时区解释，页面会显示从 `/api/health` 读取的服务端时区。

## 管理定时任务 {#manage-scheduled-jobs}

本节按钮走 REST 管理接口，可选择全部空间或当前空间。聊天里的 `schedule` 工具则固定只读控当前空间，不能查看或操作其他空间的任务内容。

1. 点击底部「任务」→「定时任务」。
2. 用「全部空间」或「当前空间」过滤，按「下次执行」「更新时间」或「创建时间」排序，并可切换升序或降序。
3. 点击任务打开详情，查看完整任务内容、最近执行结果、来源空间、任务 ID 和时间线。
4. 点击「编辑定时任务」可修改任务内容和一次性/每日时间。任务内容去掉首尾空白后不能为空，最长 2,000 字符；保存只修改此任务，不改变来源空间，页面也不支持修改来源空间。
5. 按状态使用「暂停调度」「恢复调度」「取消任务」「立即重试」或「删除任务」。这些操作都会先显示确认卡片，核对任务 ID 后再确认。

控制语义如下：

| 操作 | 实际影响 |
| --- | --- |
| 暂停调度 | 只停止后续到点触发，不停止正在执行的一轮。 |
| 恢复调度 | 只恢复已暂停任务；已过期的一次性任务不能恢复，需要新建。 |
| 取消任务 | 不再按原计划调度，也不是正在执行的聊天的停止按钮。 |
| 立即重试 | 仅失败任务可用；确认后会启动一次真实模型执行，可能产生工具、审批和费用，不会自动重复提交。 |
| 删除任务 | 永久删除此任务和页面时间线，无法从应用内恢复；不删除来源空间。 |

任务时间线只保留创建、最近一次控制和最近一次运行结果，不代表完整聊天历史。执行中或排队中时，此管理页不能修改排期；可等待该轮结束后再管理。若要停止正在执行的一轮，请到来源空间聊天页停止，并回读核对结果。

## 创建与控制网页监控 {#create-and-control-monitors}

1. 在聊天页确认当前空间。监控通知会投递到这个来源空间；删除空间会删除绑定监控。
2. 在消息中提供公网 HTTP(S) 链接、触发条件和检查间隔。例如：“监控 `https://example.com/product`，出现‘补货’就通知我，每 5 分钟检查一次。”
3. 触发条件只有两种：`change` 表示内容指纹变化；`contains` 表示指定关键词从“未命中”变为“命中”。`contains` 必须提供关键词。
4. 检查间隔以分钟为单位，最小 5，默认 30。未提供标题时使用 URL 作为标题。
5. 发送后等待模型调用 `monitor` 工具，再到底部「任务」→「网页监控」核对状态、条件、累计检查和来源空间。

`change` 的第一次检查只建立基线，不会通知；之后指纹变化才通知。`contains` 持续命中不会重复通知，只有未命中转命中会通知。页面通知中的网页摘要是不可信外部内容，只能当作事实线索核对。

管理步骤：

以下页面操作走 REST 管理接口，可按「全部空间」或「当前空间」筛选。聊天中的 `monitor` 工具固定只读控当前空间，不能查看或操作其他空间的监控标题、关键词或内容。

1. 在「网页监控」页用「全部空间」或「当前空间」过滤，按创建时间、最近检查或状态排序。
2. 「暂停」停止后续检查，「恢复」恢复已暂停监控；这两个操作直接提交，操作前先核对目标卡片。
3. 「停止」会显示确认卡片。停止是终态，不能恢复；要继续监控必须在聊天中重新创建。
4. 「删除」也会显示确认卡片，永久删除监控并停止后续检查与通知。已停止监控仍可删除记录。

当前移动端没有监控编辑表单，不能在页面修改 URL、关键词、间隔或来源空间。暂停/停止只控制后续检查；它们不会立即发起一次检查，也不会删除已观察到的待通知事实。

## 可见结果 {#visible-results}

- 定时任务到期后，来源空间的聊天页会出现以「⏰ [定时任务]」开头的用户消息并进入真实模型执行；任务详情随后显示最近结果、失败状态或下一轮时间。
- 网页监控命中后在来源空间收到以「📡 [监控]」开头的通知，列表更新累计检查、最近检查和最近通知时间。
- 活动历史中的状态与步骤会随真实执行更新；失败、拒绝、取消、过期和中断会保留，不会伪装成成功。

默认扫描周期意味着到期或到达检查间隔后，实际执行可能稍晚。若列表提示最后观测数据或操作结果未明，先刷新并核对状态；不要自动重发写操作。

## 限制与排错 {#limits-and-troubleshooting}

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 任务没有到点执行 | 服务器是否常开、来源空间是否正在运行、扫描是否稍晚 | 等待下一轮扫描；正在运行的会话会让到期任务等待。服务停机错过的一次性任务不会补跑。 |
| 重启后一次性任务消失执行机会 | 任务是否已过期 | 到期一次性任务会被禁用且不补跑；需要时新建。每日任务会重算下一次未来时间。 |
| 任务失败 | 详情中的最近执行结果和错误状态 | 失败不会自动重跑；核对影响后手动确认「立即重试」或新建任务。 |
| 每日时间不符合预期 | 页面显示的服务端时区 | 按服务端时区修改 `HH:mm`，不要按手机时区换算。 |
| 监控不通知 | 条件、最近检查、抓取错误和服务是否常开 | `change` 首检和内容未变不通知；`contains` 持续命中不重复通知。抓取失败会显示错误，不自动伪造通知。 |
| 监控抓取失败 | URL 是否公网 HTTP(S)、页面是否可访问、Web 工具是否启用 | 修正链接或稍后刷新；失败状态保留到下一次成功检查。 |
| 操作结果未明 | 页面是否显示「提交结果待核对」 | 刷新列表和详情，核对状态或条目是否仍存在，再手动解除锁定；应用不会自动重试。 |
| 看不到某次聊天 | 是否在「活动历史」寻找 | 活动只包含模型显式登记的工作；完整对话在聊天页，审批在「审批」页。 |

删除空间会同时删除该空间的活动历史、绑定定时任务和监控，且不可恢复；仅需清空聊天时使用设置页的会话重置，并按确认卡片选择是否同时清理任务和监控。
