# 新闻阅读

新闻是独立的阅读视图，不是聊天空间，也没有专属聊天框。底部「新闻」入口打开推荐与全部文章时间线；服务端在内部复用现有信息处理与模型能力，不另建推荐引擎。

## 阅读与筛选 {#reading}

- 阅读页顶端只有一行「推荐／全部」、收藏、来源与抓取操作；默认显示推荐，工具栏下直接进入文章。抓取时间、分析进度与失败数量在「来源」中查看。
- 「推荐」只显示模型已完成结构化筛选并明确选中的文章，每篇带简短理由；模型没有选中的文章仍可在「全部」中阅读。
- 「全部」按发布时间从新到旧排列；发布时间无效时使用服务端首次接纳时间。收藏筛选只过滤列表，不改变排序。
- 点按文章可阅读服务端清理后的安全文本；长按文章打开与聊天消息一致的操作菜单，不会同时进入详情。详情中也可以长按标题或正文打开菜单。原文链接只允许无凭据的 HTTP(S) 地址；外部标题、正文和链接都属于不可信内容。
- 服务重启后，已接纳文章、推荐结果、反馈和收藏仍从服务端恢复。

## 管理 RSS 源 {#sources}

1. 点击新闻阅读页顶部的「来源」图标，添加一个 RSS2 源的公网 HTTP(S) 地址，可同时设置展示标题。
2. 添加时服务端会实际抓取并校验 XML；带用户名或密码的 URL 会被拒绝。
3. 来源页显示抓取时间、等待分析和分析失败数量；源列表显示各源最近抓取时间与受控错误。某个源损坏或暂时不可用时，其他源和已读文章仍可使用。
4. 删除源只停止后续采集；已经接纳的文章、评论、喜欢/不喜欢和收藏不会被删除。

服务端默认每 30 分钟采集一次；后台采集只抓取新条目，不会自动重排已知失败的文章。手动刷新先完成 RSS 抓取并返回新增数量，文章分析在后台继续；刷新不会等待模型整轮结束，也不会自动重复提交未明结果。条目缺少标题或可读正文时，整个源会记录受控解析错误，而不是静默当作空源。

## 反馈与推荐 {#feedback}

- 长按文章后，在菜单中选择喜欢、不喜欢、收藏或评论；点按菜单外部或按 Android 返回键只关闭菜单。读屏用户可使用文章的「打开文章操作」自定义操作。
- 喜欢与不喜欢互斥，再次选择已选反应可撤销；收藏独立于喜欢/不喜欢，可在菜单中取消收藏。
- 没有反馈时不显示操作按钮行；已有反馈以小徽标显示，点按徽标可重新打开菜单。
- 菜单中的「评论」进入文章详情的评论区。评论按文章保存，支持新增和删除；空白评论会被拒绝，单条最多 4000 字符。
- 反馈不会立即触发模型。下一次后台分析会读取近期文章、反馈、评论和收藏作为局部证据；收藏是较弱信号。
- 「明确偏好」由用户保存；「模型推断」是服务端从反馈更新的摘要。两者分开保存，推断摘要不会覆盖明确偏好、空间规则或全局用户资料。
- 新建内部新闻空间的默认规则要求推荐理由和模型推断摘要使用简洁的简体中文；RSS 标题和正文保留原文，不自动翻译。

新闻 V1 可以不提供明确的偏好编辑页；若当前客户端未显示该入口，不代表服务端会改写或丢弃已有偏好。

## 刷新与失败 {#refresh}

- 阅读页顶部的刷新图标发起一次手动抓取；列表读取失败时另显示「重试列表」，只回读列表和状态，不重新抓取。手动抓取已运行时返回冲突，不会排队或并发抓取。
- 抓取写入结果未明时，先回读状态并核对，再明确解锁；客户端不会自动重发。
- 采集失败会在新闻状态或源列表显示受控错误，不会把坏源静默当成空源。
- 模型分析失败时，全部时间线仍可读；推荐视图只显示已经确认成功的结果。
- 再次手动刷新可以重新排队已知失败的文章；正在运行的批次不会被重排。
- 新闻页只在前台且状态显示处理中时短时回读状态和列表，终态后停止；新闻不使用新的 SSE 或全局轮询。

## 边界 {#boundaries}

新闻 V1 不做全文网页抓取、搜索、向量推荐、系统通知、OPML 或主会话新闻工具，也不支持把文章携带到聊天。内部新闻空间不会出现在普通空间列表，也不能通过聊天、空间重置或删除入口操作。
